# Application Gateway custom status pages

Generic custom HTML pages for Azure Application Gateway custom error/status responses.

This folder contains multiple page sets:

- `generic/` - polished neutral status pages.
- `star-wars/` - brand-safe galactic sci-fi themed status pages.

The pages are standalone and include inline CSS, so they do not depend on external assets.

## Status code mapping

| Status code | Azure portal label | File |
| --- | --- | --- |
| 400 | Bad request | `400-bad-request.html` |
| 403 | Forbidden | `403-forbidden.html` |
| 405 | Method not allowed | `405-method-not-allowed.html` |
| 408 | Request timeout | `408-request-timeout.html` |
| 500 | Internal Server Error | `500-internal-server-error.html` |
| 502 | Bad Gateway | `502-bad-gateway.html` |
| 503 | Service Unavailable | `503-service-unavailable.html` |
| 504 | Gateway timeout | `504-gateway-timeout.html` |

## Application Gateway requirements

Application Gateway custom error pages must meet these requirements:

- Each page URL must be publicly reachable by Application Gateway.
- Each page URL must return HTTP `200`.
- Each page URL must point directly to a `.htm` or `.html` file.
- Each HTML file must be smaller than 1 MB.
- Custom status pages are displayed only for errors generated by Application Gateway itself. Backend-generated error bodies are passed through unchanged.

## Azure Blob Storage hosting

Azure Blob Storage works well for these pages, but anonymous Blob access must be enabled in two places:

1. **Storage account**: allow Blob anonymous access.
2. **Container**: set the public access level to **Blob**.

The Application Gateway custom error URL should use the direct Blob endpoint, for example:

`https://<storage-account>.blob.core.windows.net/<container>/<file>.html`

Example base URL when the files are uploaded to a container named `status-codes`:

`https://<storage-account>.blob.core.windows.net/status-codes`

> Avoid CDN-fronted URLs for Application Gateway custom error pages. The gateway must be able to fetch the HTML file directly from a publicly accessible origin.

### Setup example

Use these commands as a reference when preparing a storage account/container for status pages:

```powershell
$resourceGroupName = '<resource-group-name>'
$storageAccountName = '<storage-account-name>'
$containerName = 'status-codes'
$sourcePath = '.\generic'

az storage account update `
	--resource-group $resourceGroupName `
	--name $storageAccountName `
	--allow-blob-public-access true

az storage container create `
	--account-name $storageAccountName `
	--name $containerName `
	--public-access blob `
	--auth-mode login

az storage blob upload-batch `
	--account-name $storageAccountName `
	--destination $containerName `
	--source $sourcePath `
	--overwrite true `
	--auth-mode login
```

Validate one of the uploaded files returns HTTP `200`:

```powershell
Invoke-WebRequest `
	-Uri "https://$storageAccountName.blob.core.windows.net/$containerName/502-bad-gateway.html" `
	-Method Head
```

## Configure a listener

Use `./Set-AppGatewayListenerCustomStatusCodes.ps1` to apply all 8 custom status pages to a selected Application Gateway listener.

The script requires:

- Azure subscription ID
- Application Gateway resource group
- Application Gateway name
- Public HTTP/HTTPS base URL where one page set is hosted

Example using the hosted Blob container URL directly:

```powershell
./Set-AppGatewayListenerCustomStatusCodes.ps1 `
	-SubscriptionId '<subscription-id>' `
	-ResourceGroupName 'rg-x-bwc-agw-dev-weu' `
	-ApplicationGatewayName 'agw-bwc-dev-weu' `
	-StatusCodePath 'https://<storage-account>.blob.core.windows.net/status-codes'
```

Example using a local folder for file validation and a hosted public base URL for Application Gateway:

```powershell
./Set-AppGatewayListenerCustomStatusCodes.ps1 `
	-SubscriptionId '<subscription-id>' `
	-ResourceGroupName 'rg-x-bwc-agw-dev-weu' `
	-ApplicationGatewayName 'agw-bwc-dev-weu' `
	-StatusCodePath './generic' `
	-PublicBaseUrl 'https://<storage-account>.blob.core.windows.net/status-codes'
```

The script shows a numbered menu of Application Gateway listeners. Pick a listener by number, confirm, and it assigns these listener-level `customErrorConfigurations`:

- `HttpStatus400`
- `HttpStatus403`
- `HttpStatus405`
- `HttpStatus408`
- `HttpStatus500`
- `HttpStatus502`
- `HttpStatus503`
- `HttpStatus504`

Use `-DryRun` to write the generated ARM payload to a temporary file without updating Azure.
